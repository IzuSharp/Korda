# Repository instructions

- Target Native AOT for product libraries. Run compiled consumers directly on the Linux runner and skip JIT consumer builds and tests. Run clean-image and CPU emulation checks only on explicit request.
- Publish only independently installable top-level packages. Bundle their internal components and native assets. Keep internal modules independently buildable and testable.
- Register each new module's source and test paths, dependencies, checks, and any package outputs. Follow the [module registration guide](eng/ci/modules/README.md).
- PR and main CI use the committed diff and module dependencies to select checks. Inspect the plan with `python3 eng/ci/impact.py origin/main`. If it misses affected consumers or selects unrelated work, fix and test the routing in the same PR. Run each required check once and independent checks in parallel.
- For every NuGet package, verify metadata-only edits against the `.nupkg` ID, version, README and description. Skip API signature checks for those edits. For C# source, generator, project-reference or API-baseline changes, check affected APIs by module dependency. When packer changes can replace assemblies, reuse build outputs to verify the shipped DLLs and XML docs. See [check selection](eng/ci/database_plan.py), [metadata validation](eng/ci/validate_public.py) and [packed API checks](eng/ci/packed_api.py).
- Validate each affected top-level package in its own runner. On main, compare every registered package with its last published inputs. Build, consume and publish the exact next preview for each missing or changed package.
- Follow the [public API naming conventions](CONTRIBUTING.md#public-api-naming) when adding or changing public names, and update generators, documentation and compilable examples together.
