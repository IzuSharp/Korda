# Database previews

Pull requests run the checks selected by `python3 eng/ci/impact.py BASE`. Module ownership, test commands and top-level packages are registered under [eng/ci/modules](../eng/ci/modules/README.md). When a public package input changes, the planner compares both providers’ input hashes with nuget.org and includes any outstanding release. Merging only documentation or tests outside the packages skips the registry lookup, candidate promotion and database build. Check the CI summary for the reason a lane was selected.

For a documentation-only PR the planner, dependency review and secret scan run without a database runner. A single-provider regression selects its own native build and tests. Editing both providers’ regression suites schedules the two single-provider jobs in parallel. Pure generator, MSBuild task API and ELF profile test changes select their own checks independently. Packaging metadata changes can reuse the signed native assets and still test the resulting archives in real applications. A change to the shared database runtime exercises both providers. Unregistered source paths report an ownership error. CodeQL selects the affected supported languages; weekly validation scans both.

The public package allowlist contains **NativeWeave.Database.Sqlite** and **NativeWeave.Database.PostgreSql**. Each package includes the shared managed assemblies, build integration, generator, third-party notices and its selected provider library. Internal component packages and HelloWorld receive no new public versions.

Each candidate uses `0.1.0-preview.<CI run number>.2`. The PR validates the Git integration tree and retains the exact tested files. On merge, CI looks up the successful same-repository PR run. A matching tree, package selection and artifact allow promotion; a stale, missing or external candidate requires a fresh main build. Direct pushes, manual runs and scheduled checks cannot publish. The trusted `release.yml` job checks the allowlist and hashes before authentication, polls nuget.org every two minutes, verifies signed payloads and runs consumers against the registry. Rerun a failed release job to reuse its immutable candidate.

GitHub Actions can restore caches from the base branch. PR caches remain scoped to their merge ref. The weekly or manual full run on main also warms the default-branch caches for subsequent PRs.

Manual CI with empty inputs runs full Linux validation. Set `check_paths` to tracked test or documentation files (one per line) to time the same check selection on a hosted runner; these replays are ineligible for promotion. Weekly CI runs the full compatibility, sanitizer, clean-image and recovery gates. The internal twelve-package feed remains available for historical compatibility work.
